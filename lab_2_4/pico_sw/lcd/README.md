# pico_sw - Raspberry Pi Pico deployment project

## What's in here

- **`uart_inference.cpp` - the main way to test your model.** Send a
  784-pixel MNIST image as a line of text over USB-serial (or a real UART
  wire), get back the predicted digit, inference time, and per-class
  confidence scores. No LCD or touchscreen hardware required - this is the
  path everyone can use regardless of what hardware you have.
- `host_scripts/send_image.py` - a ready-to-use Python script that sends an
  image from your own MNIST `.npz` cache or a PNG of your own handwriting,
  and prints the Pico's response.
- `arena_size_test.cpp` - headless: initializes the model and prints the
  actual tensor arena usage every second over serial. **Run this first**,
  before any of the other targets.
- `inference_test.cpp` - headless: runs inference against 10 built-in real
  MNIST test images (one per digit, see `models/mnist_image_data.cpp`) and
  prints actual vs. predicted, with a running accuracy count. A good
  zero-setup smoke test before wiring up `uart_inference` from a host script.
- `main.cpp` - **optional fun extra** if you have the Waveshare LCD
  touchscreen: draw digits directly on the display and see live predictions.
  Not required for the lab - everything the lab asks for is covered by
  `uart_inference` + `send_image.py`.
- `src/` - the model wrapper (`model.h/.cpp`), settings (`model_settings.h`),
  and the shared inference code the test harnesses use.
- `models/` - `mnist_model_data.cpp` (your converted model, generated by the
  Python notebook's Part C) and `mnist_image_data.cpp` (10 built-in test
  digits).
- `lib/` - vendored dependencies: `pico-tflmicro` (TensorFlow Lite Micro for
  the Pico), `lcd`/`font`/`config` (Waveshare LCD touchscreen driver, only
  needed for the optional `main.cpp` path).
  These are included directly rather than as git submodules - nothing to
  initialize separately, but if your course setup expects real submodules
  instead, these can be swapped in without touching anything else in this
  project.

## Build order

1. Copy `mnist_model_data.cpp` (generated by the Part C notebook cell) into
   `models/mnist_model_data.cpp`, replacing the placeholder.
2. Build and flash `main_arena_size_test` first. Read the printed tensor
   arena size over serial, then set `arena_size` in `src/model_settings.h`
   to that value plus a small safety margin.
3. Build and flash `main_inference_test` to confirm the model predicts
   correctly on the 10 built-in test digits (zero setup - no host script
   needed, just watch the serial output).
4. Build and flash `main_uart_inference`, then use `host_scripts/send_image.py`
   from your computer to send real images and get predictions back:
   ```
   cp ~root/.keras/datasets/mnist.npz .
   python host_scripts/send_image.py /dev/ttyACM0 --npz mnist_cache.npz --index 42
   python host_scripts/send_image.py /dev/ttyACM0 --png my_own_digit.png
   ```
5. **Optional, if you have the LCD touchscreen:** build and flash `main` for
   the interactive drawing version.

This produces a separate `.uf2` for each target above (`main.uf2`,
`main_arena_size_test.uf2`, `main_inference_test.uf2`,
`main_uart_inference.uf2`).

## The uart_inference protocol

**Host -> Pico:** one line, 784 pixel values (0-255), comma- or
whitespace-separated, row-major (same order as the MNIST arrays used
throughout this lab), terminated by `\n`.

**Pico -> Host:** one line back -
```
OK,<predicted_digit>,<inference_time_us>,<score_0>,<score_1>,...,<score_9>
```
or, on bad input,
```
ERROR,<message>
```
`send_image.py` handles building and parsing this for you; the protocol is
documented in full at the top of `uart_inference.cpp` if you want to write
your own client (e.g. to batch-test your whole handwritten-digit set from
Lab 2.2 in one script and compute accuracy on-device automatically).

## A correctness note on image quantization

The model's input tensor is `int8`, quantized against training data that was
normalized to `[0, 1]` (matching the Lab 2.2 notebook's preprocessing) -
**not** raw `0-255` pixel values directly. `Model::set_input_image()`
handles this by reading the tensor's actual `(scale, zero_point)` at
runtime (via `input->params`) rather than assuming fixed values, so it stays
correct even if you requantize with different representative data later.
`Model::get_output_scores()` does the equivalent dequantization on the way
out, so the confidence scores you see are real probabilities, not raw int8
values.
